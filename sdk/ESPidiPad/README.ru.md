# ESPidiPad

English: [README.md](README.md).

**M-VAVE SMC-PAD Pro** по Bluetooth LE как контроллер для прошивки ESPidi: его 16 пэдов (8 банков), 8 энкодеров и 5 кнопок приходят событиями в `loop()`, а 128 RGB-подсветками пэдов можно управлять. Прошивка самого пэда не меняется — для своего приложения и других хостов он остаётся обычным SMC-PAD.

Основа — **кит SMC-PAD Pro по BLE** Руслана Мазавина (pi32v2_re), лежит без изменений в [`extras/smc_pad_ble/`](extras/smc_pad_ble/): протокол ([PROTOCOL.md](extras/smc_pad_ble/PROTOCOL.md)), эталонная реализация и C++-сборщик пакетов, которым пользуется библиотека. Авторство — ниже.

## Быстрый старт

Нужен Arduino-ESP32 **3.3 или новее** (его BLE-библиотека на ESP32-C3 работает на NimBLE). Скопируйте `sdk/ESPidiPad` (и `sdk/ESPidiHub`) в папку `libraries` Arduino.

```cpp
#include <ESPidiHub.h>
#include <ESPidiPad.h>

espidi::Pad pad;

void setup() {
  pad.begin();                       // сам переподключается к запомненному пэду
}

void loop() {
  espidi::PadEvent e;
  while (pad.read(e)) {
    switch (e.kind) {
      case espidi::PadEvent::PAD:     // e.index 0-127 = e.bank() * 16 + e.pad(); e.value = сила удара, 0 = отпущен
        if (e.value) pad.setColor(e.index, 255, 40, 0);
        break;
      case espidi::PadEvent::ENCODER: // e.index 0-15, e.value, e.delta
        break;
      case espidi::PadEvent::BUTTON:  // e.index 0-4, e.value 1 = нажата
        break;
      default:                        // MIDI, CONNECTED, READY, DISCONNECTED, PAIRED, PAIR_FAILED
        break;
    }
  }
}
```

Начните с [`examples/PadLab`](examples/PadLab/PadLab.ino): сопряжение, все события на OLED, подсветка и отчёт для стенда.

## Сопряжение

Один раз на плату: переведите пэд в режим сопряжения Bluetooth (см. его инструкцию) и вызовите `pad.pair()` — например, по кнопке. Библиотека 30 секунд ищет пэд, проверяет его идентификатор (`SMC-PAD_…`), сопрягается с bond (just works) и запоминает пэд в NVS-пространстве **`espidi_pad`**, общем для всех прошивок на плате: после этого любая прошивка с ESPidiPad подключается к нему обычным `begin()`. `pad.forget()` — или **FORGET PAD** в меню HUB — забывает его.

`state()`: `NO_PAD` → `PAIRING` → `CONNECTING` → `SYNCING` (`progress()` 0-100) → `READY`.

## События

Что шлёт каждый контрол, задаётся в активном профиле пэда, и библиотека читает этот профиль при подключении (PROTOCOL.md 2.2) — поэтому знает, что, скажем, нота 36 на 10-м канале — это пэд 0, а CC 30 — энкодер 0, как бы их ни настроили в MidiSuite.

| `kind` | `index` | `value` | `delta` |
|---|---|---|---|
| `PAD` | запись пэда 0-127 (`bank()`, `pad()`) | сила удара, 0 = отпущен | |
| `ENCODER` | запись энкодера 0-15 | что он прислал | изменение; относительные энкодеры ±1 |
| `BUTTON` | 0-4 | 1 нажата, 0 отпущена (у триггера и переключателя — только нажатие) | |
| `MIDI` | | | |

У каждого события есть исходное сообщение в `midi[]` / `len`, так что прошивка может просто пропускать MIDI дальше. Пока профиль не прочитан (`READY`), всё приходит как `MIDI`. От энкодеров ждите пачек: пэд шлёт каждый шаг быстрого поворота [firmware].

## Подсветка

`setColor(pad, r, g, b)`, `fillBank(bank, r, g, b)`, `getColor()`. Цвета живут в RAM пэда: показываются сразу и не изнашивают флеш [firmware, capture]. Вызовы только запоминают желание; фоновая задача шлёт по одному запросу (пэд выбрасывает всё, что пришло, пока он занят), последний цвет — первым, а банк целиком одним пакетом, если в нём поменялось четыре пэда и больше. Цвета, заданные прошивкой, возвращаются после переподключения и после смены профиля на пэде.

## Что ещё не подтверждено

Часть фактов кит помечает [open], пока стенд Руслана их не подтвердит ([OPEN_QUESTIONS.md](extras/smc_pad_ble/OPEN_QUESTIONS.md)). Библиотека на них не опирается:

- **Время подключения.** MidiSuite перед записью читает все 28 КиБ профилей (31 обмен), и библиотека по умолчанию тоже (`PadOptions::fullSync = true`). Если стенд покажет, что это не нужно, `fullSync = false` читает только активный профиль (6 обменов).
- **Сопряжение**: нужен ли пэду bond, тип адреса, MTU и интервал соединения — PAD LAB их печатает.
- **Пэды**: шлют ли силу удара или постоянное значение — в `value` то, что прислал пэд.
- **Записи энкодеров 8-15** (ручек у пэда 8): приходят под своим номером.
- **Цвета после выключения**: скорее всего теряются; библиотека перекрашивает после переподключения.

## Правила, которые соблюдает библиотека (и вы тоже)

Из [AGENTS.md](extras/smc_pad_ble/AGENTS.md) кита, их обеспечивает `SmcPadProtocol.h`:

- во флеш пэда не пишется ничего: ни регион 0, ни калибровка (регион 3), ни `save0` — такого вызова в библиотеке просто нет;
- один запрос настройки в полёте, с таймаутом и повтором; каждый доступ с проверкой границ;
- записи пишутся целиком, из байтов, прочитанных с пэда.

Не обращайтесь к сервису настройки пэда (`AE40`) сами и не собирайте пакеты руками: нужное добавляйте в библиотеку по разделу кита «Changing the protocol code».

## Размер

BLE-стек и библиотека добавляют около 330 КБ флеша: PAD LAB собирается в 715 КБ (слот 768 КБ), шаблон без BLE — в 388 КБ. Рядом с большинством прошивок помещается.

## Тесты

```bash
python3 -m unittest discover -s tools/tests       # проверки кита + PadCore.h против эмулятора пэда
```

`extras/test/test_padcore.cpp` гоняет `PadCore.h` (последовательность подключения, повторы, подсветка, смена профиля, разбор событий) против эмулятора пэда на компьютере; ожидаемые байты берутся из эталона кита на Python (`make_padcore_vectors.py`) — полная синхронизация совпадает с захваченной сессией MidiSuite байт в байт. С настоящим пэдом это ещё не запускалось: для этого PAD LAB.
